Each node module defines `class Utils(Protocol)` and a concrete `SystemUtils`; the node is `@dataclass(frozen=True)` with `utils: Utils = field(default_factory=SystemUtils)`. `Count()` is production wiring and `Count(fake)` is for tests, replacing Rust's Count<U = SystemUtils>, new()/with_utils() and the &MockUtils trick for keeping ownership of recording mocks. Walks follow the same pattern: a frozen dataclass subclassing Walk[Id, State] whose node fields default to production nodes, so tests build `Counter(start=Start(script), ...)`. Fakes are small hand-written classes rather than unittest.mock so pyright checks them against the protocol. Tests live in tests/ (not inline); walk modules keep State/Id/Counter un-underscored because pyright strict reportPrivateUsage rejects test imports of _names, and __all__ = ["Error", "run"] marks the real public surface.
