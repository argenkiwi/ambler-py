`--state board:my_app.board.Board` used to be written verbatim, so nodes/__init__.py referenced `my_app` without importing it and pyright failed. utils/source.resolve_type now shortens each name-only attribute chain (`a.b.Type`, also inside generics like `list[a.b.Type] | None`) to `Type` and records `from a.b import Type`, unless the chain's first name is already bound in init (`import datetime`, `from my_app import board`, a class with members): then it is kept as written and reuses that import. Every other name must be a builtin or bound in init, otherwise the command exits 2 with a hint to give its path (issue #11 left reject-vs-warn open; we chose reject so generated code never fails pyright). Quoted types exit 2 too, except strings inside `Literal[...]`. A shortened name that clashes with what init binds, with another --state item's import, or with what the node's test imports for itself (the node class, Outcome, dataclass, field) also exits 2. `_origins` records `import a.b` under `a`, the name it really binds. render_protocols merges the new imports into init's leading import block and re-renders it in isort's section order, so it is right even when ScaffoldUtils.format cannot find ruff (it runs `sys.executable -m ruff` and swallows failures); only odd blocks (comments, relative or scattered imports) fall back to appending after the last import. New protocols are skipped by declared class name, not substring, so HasCount is still written next to HasCountdown.
